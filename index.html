Content Creation -- Prompt 1

The Angle Finder

I want to write a blog post about [TOPIC] for [AUDIENCE]. Before writing anything, generate 10 unconventional angles on this topic. For each angle, write one sentence explaining why a reader would click on it over the 50 other articles on the same subject. Rank them by originality.

Forces the AI to compete with existing content rather than producing another generic take -- the #1 reason blog posts fail.

Business & Marketing -- Prompt 12

The Cold Email That Gets Replies

Write a cold email to [RECIPIENT ROLE] at [COMPANY TYPE] pitching [YOUR SERVICE/PRODUCT]. Rules: - Subject line: 4-7 words, lowercase, no punctuation -- looks like a peer forwarded it - First line must reference something specific about their company - Body: under 90 words total. State the problem you solve, one proof point, and a low-commitment CTA - No "I hope this email finds you well" - No "I'd love to pick your brain" - Sign off with just your name and one line of context, no essay signature Industry: [INDUSTRY]. Your unique differentiator: [DIFFERENTIATOR].

The 90-word constraint forces ruthless prioritization, and the "peer-forwarded" subject line technique has 2-3x higher open rates than formal subject lines in B2B cold email data.

Technical & Development -- Prompt 54

The Code Review Prompt

Review this code for production readiness: [PASTE CODE] Review for: 1. BUGS: Actual errors, edge cases, off-by-one errors, null/undefined risks 2. SECURITY: Injection vulnerabilities, exposed secrets, missing input validation 3. PERFORMANCE: N+1 queries, unnecessary loops, missing indexes, memory leaks 4. MAINTAINABILITY: Naming clarity, function length, single responsibility, magic numbers 5. ERROR HANDLING: Missing try/catch, swallowed errors, unhelpful error messages For each issue found: - Line number or code snippet - Severity: CRITICAL / WARNING / SUGGESTION - Explanation of why it's a problem - Fixed code snippet If no issues in a category, say "No issues found" (don't manufacture problems).

Categorized review with severity levels mimics how senior engineers review code, and the "don't manufacture problems" instruction prevents the AI from nitpicking working code just to seem thorough.
